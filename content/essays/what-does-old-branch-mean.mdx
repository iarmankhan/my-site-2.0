I named a flag `--age` in [git-tidy](/writing/git-tidy). It does not measure when someone created a branch name.

A branch points to a commit. For `--age`, git-tidy reads `%aI` from the commit at the tip of that branch. That is the commit's **author date**, which can differ from its committer date. Git-tidy compares it with the number of days you supplied.

Take two fictional branches. `feature/a` is created today at a commit authored four months ago. `feature/b` has existed for four months but now points to a commit authored today. With `--age 90`, the first can appear in the results and the second will not. Neither result tells you when the branch name was created.

You can preview the age filter without deleting anything:

```bash
npx git-tidy-cli --age 90 --scope remote --json
```

Read that output as a candidate list. An old author date does not establish that a branch was merged or that nobody still needs it. Check the repository's actual default branch and review each candidate before deletion. In git-tidy 2.1.0, remote-only branches can be reported as unmerged, so I would verify merge status separately rather than use `--merged --scope remote` as a deletion recipe.

Here, "old" means the tip commit's author date passed the filter. It is one useful fact about a branch, not the decision to delete it.

The details are in [git-tidy's branch collection](https://github.com/iarmankhan/git-tidy/blob/main/src/services/git.ts), its [filter code](https://github.com/iarmankhan/git-tidy/blob/main/src/services/branch-analyzer.ts), and [Git's date format documentation](https://git-scm.com/docs/pretty-formats).
