A function returns `NaN`. A coding assistant reads the source and offers three plausible explanations. None tells you what reached the failing line in that run.

An agent has to turn a guess into a measurement. [agentic-debugger](https://github.com/iarmankhan/agentic-debugger) exposes tools to start a debug session, insert a probe at a file and line, read captured values, and remove the probe. The failing case still has to be reproduced.

Take this fictional JavaScript line:

```js
const total = subtotal - discount;
```

A probe immediately after it could capture `subtotal`, `discount`, and `total`. Suppose the log shows `discount` as `"10%"`. That points toward a parsing or data contract problem. It does not tell you where the string entered the system.

No log entry does not prove the line never ran. The reproduction may have missed it, the probe may be misplaced, or the HTTP request may have failed. Check the path and the collection step before drawing a conclusion.

The probe changes the source file and sends selected values to an HTTP server on the debugging machine. Choose values you are comfortable logging. After reading them, remove the probes, stop the session, and inspect the diff. Then run the failing case again to test the fix.

For a useful debugging answer, the agent should name the value it needs, show what it observed, and leave the source clean before offering a patch.

The implementation is in the [MCP tools](https://github.com/iarmankhan/agentic-debugger/blob/main/src/index.ts), [probe code](https://github.com/iarmankhan/agentic-debugger/blob/main/src/instrumenter.ts), and [log server](https://github.com/iarmankhan/agentic-debugger/blob/main/src/server.ts). The `NaN` case and `"10%"` value above are fictional, not a recorded debugging run.
